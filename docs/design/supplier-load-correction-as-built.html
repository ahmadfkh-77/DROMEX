CORRECT SUPPLIER LOAD — AS IT IS BUILT TODAY

This is the Supplier Load correction page that is already in the app (DEC-525), drawn from its code and your screenshots: the whole workflow first, then every screen and state. It is a reference of what exists, not a new design.

THE WORKFLOW

1 · Open a loadFrom Supplier history (or Load History), tap a supplier load. It opens the correction page.
›
2 · The pageA plain list of the load. Each line has Edit. Nothing changes yet. The bar shows TOTAL.
›
3 · Edit one lineTap Edit: only that line opens in a small sheet with "Was …". Done keeps it, Cancel throws that edit away.
›
4 · See the changeThe line shows the old value crossed out beside the new one. The bar now says "N CHANGES", and Review turns on.
›
5 · ReviewA sheet lists every old and new value and the new total, and asks for the required reason. Save correction.
›
6 · Saved"Supplier load corrected. Totals, balance, and audit history were updated." The original is kept in the history.
Cancel a loadRed link Cancel this load at the bottom → its own screen with the warning and a required reason → "Cancel this supplier load?" → the load stays in history, out of totals.
ReactivateA cancelled load opens the same page with its reason. Correct what is wrong, tap Reactivate, give a reason: it becomes active again, no duplicate.
Leaving earlyBack with unsaved changes asks "Leave without saving?" (Keep editing / Leave).
Payments lockWith an active payment the Supplier line shows Locked, and a note explains why. Everything else can still be corrected.

THE PAGE

THE EDIT SHEETS — ONE PER LINE

REVIEW, SAVE, CANCEL AND REACTIVATE

Rules behind these screens (unchanged by anything else)

  • Lines that can be corrected: Date, Supplier, Delivered to, Item, Quantity (with Pieces and the steel fields), Delivery, Ticket / invoice, Price (with VAT) and Notes. The load number and the time of day never change.
  • Date: a normal audited change with a required reason, not in the future and inside the project's dates. It is refused while the load is in an active Stock batch.
  • Payments: the supplier is locked while an active payment exists; changing to Unpriced is blocked too. Balances and status recalculate.
  • Reason and history: every correction stores the reason, time, the user and the old and new values. Quantity Target links, steel details, price and VAT rules and the database are unchanged by this page.
  • Total: recalculated from the price, shown crossed out beside the new one if it changed.
