# DROMEX Application Audit — 2026-08-14

## Verified gates

- TypeScript static check: passed.
- Automated domain/workbook suite: 84 tests across 12 files, all passed, including cancellation, 4,000-load/8,000-payment reconciliation, native charts, Arabic RTL localization, and embedded-photo workbook structure.
- Expo Doctor: 18/18 checks passed after moving Android 10 configuration to `expo-build-properties`.
- Android production export: passed, 770 modules bundled to Hermes bytecode.
- iOS production export: passed, 772 modules bundled to Hermes bytecode.
- Excel relationship regression: filtered parent records retain all linked active and cancelled payment details.

## Defects corrected during the audit

- Rejected impossible and future financial dates instead of accepting text that only looked date-shaped.
- Rejected scientific notation, malformed numbers, non-finite numbers, and sub-cent prices where ordinary decimal input is required.
- Added repository-boundary validation for catalog records and stale project, supplier, driver, truck, and equipment relationships.
- Rechecked a payment target inside the write transaction so rapid submissions cannot overpay a balance using stale UI state.
- Added an explicit daily-report conflict message for another report already using the same project and work date.
- Preserved fuel gauge previous-balance and variance fields when recalculating the ledger.
- Prevented invalid daily-report material rows from failing silently.
- Added local interruption recovery for quarry purchases, Quick Text, fuel entries, and new daily project reports.
- Prevented cancellation of an old fuel movement from deleting an unrelated in-progress fuel draft.
- Removed visible mojibake from Financials and Quarry Purchases labels.
- Corrected Android 10 build configuration for the installed Expo SDK.

## UX fatigue findings

The shared page, card, field, searchable-select, feedback, and button system provides a consistent base. Autosave now protects the longest operational forms. Remaining high-value friction work is:

1. Add an explicit Review screen before confirmation to quarry and fuel workflows so all business records visibly follow Draft → Review → Confirm.
2. Add Quick Add where a required catalog/profile choice is commonly missing, with duplicate detection before creation.
3. Add a visible Draft/Trash manager instead of relying only on automatic single-draft restoration.
4. Perform hands-on accessibility and usability sessions on the target iPhone, Android phone, and Xprinter terminal, including large text, keyboard overlap, one-handed reach, sunlight contrast, and repeated-entry timing.

## Not yet certifiable

The audit cannot certify features that are still planned rather than implemented: Firebase authentication/synchronization/recovery, complete backup restore, and dashboard analytics. Physical receipt/Quick Text printing and final on-device Excel viewer behavior require the actual phone/printer models, Android version, paper widths, connection method, installed Excel-compatible viewer, and repeated acceptance tests.

## Dependency risk

`npm audit` reports 18 transitive advisories in Expo/Metro build tooling (11 high, 7 moderate). The proposed automatic force fix crosses major framework versions and is not safe to apply blindly. Runtime application code does not directly import the implicated packages; resolve this through a planned Expo/React Native upgrade and repeat the full build/device test matrix.
